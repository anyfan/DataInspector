# 对象与派生数据调研（2026-10-10）

状态：研究建议，未实现。本文不代表现有功能或已批准的实施计划。

后续状态：用户批准开始实现后，首版对象与派生功能已进入代码；实际范围和边界以 [现行用户指南](../user-guide/objects-and-derived-data.md) 为准。本文保留当时完整调研，不代表所有建议都已实现。

## 需求与结论

用户希望把同一实体的数据组织为对象，例如飞机绑定经纬高、姿态、三轴测量和状态字，再从对象派生其他曲线。三轴加速度只是例子；一个 u8 状态字拆成 8 条位信号同样属于核心需求。

建立通用的“对象 + 数据绑定 + 派生规则”机制。对象提供语义和复用上下文，派生规则负责计算，时间图和航迹是对象或派生结果的消费者。

用户已确认的管理约束：只有对象能够创建和管理派生数据。所有派生规则与输出必须归属于一个对象，不允许游离的派生信号。单个状态字也须先绑定到对象，再执行拆位；对象可以只包含一个字段，不要求完整的飞机数据。

## 当前代码核对

- `src/quick/sessiondocument.h`：会话当前为 v6；`SessionTrajectoryEntry` 已有稳定身份、坐标与姿态来源，但保存于每个子图的航迹配置中。它是可复用的基础，尚非全局对象模型。
- `src/quick/render/trajectorybuilder.*`：位置分量之间、姿态分量之间分别要求相同原始时间基；位置与姿态在共享游标下分别取最近原始样本。这种显示配对不能直接作为跨组定量计算的时间对齐策略。
- `src/quick/render/plotseriesstore.h`：值为 `double`，来源描述是文件/表/列，没有通用派生来源、整数位宽、单位与坐标系语义。
- `docs/user-guide/trajectory.md`：地理显示的水平坐标为局部切平面投影，Z 为原点记录高度减当前记录高度。显示投影不能直接充当严格三维测地计算的输入。
- 现有不可变 Store、后台任务、曲线绘制、游标、导出和模板基础可复用，但必须补齐派生身份和依赖关系。

## 用户模型

```text
对象：飞机 A
  位置：纬度 / 经度 / 高度
  姿态：滚转 / 俯仰 / 航向，或四元数
  向量：机体加速度 XYZ、速度 XYZ……
  标量：温度、压力……
  状态字：飞控状态 u8
  派生数据
    加速度模长
    飞控状态.bit0：就绪
    飞控状态.bit1：故障
    飞控状态.bits2_4：工作模式
    用户公式……
```

对象可以是飞机、车辆、设备或试验件，不要求具备位置与姿态。允许多个命名数据组，例如 IMU1/IMU2；不要把所有三轴量绑定到唯一一个“加速度”槽。

对象是来源引用，不复制原始数据。同一信号可以被多个对象引用；取消某个视图的显示不解除对象绑定。

对象是派生数据的唯一管理入口。对象列表统一管理新增、重命名、字段绑定、派生规则、有效性和配置复用；原始来源树保留原始信号浏览与绘图，不提供直接创建派生规则的入口。

每条派生规则及其输出记录稳定的所属对象身份。首版规则仅引用本对象绑定字段和本对象已有派生结果，以保持依赖范围清楚。未来如支持跨对象比较，仍须指定结果所属对象，并显式记录外部依赖，不生成无归属结果。

删除对象前预览受影响的派生结果与视图引用；确认后移除对象所属规则、结果和视图引用，保留原始文件与信号。移除字段绑定时提示依赖规则，可保留规则为“缺少来源”以便重新绑定；不继续展示过期结果。绘图显隐与对象/规则生命周期分开管理。

## 首批派生规则

| 类别 | 用户输入 | 输出与关键约定 |
| --- | --- | --- |
| 状态字拆位 | 信号、u8/u16/u32、所选位、名称 | 多条 Boolean 信号；默认 bit0 为最低有效位，明确编号约定 |
| 位段提取 | 起始位、位数、有无符号 | 整数/枚举曲线；有符号位段按所选位宽二补码解释 |
| 数值换算 | 比例、偏置、单位 | `a*x+b`，保留来源与换算参数 |
| 条件/逻辑 | 比较、AND/OR/NOT、条件选择 | Boolean 或数值信号；缺失输入默认传播缺失 |
| 向量组合 | 两/三轴来源 | 模长、分量、点积等；不要求关联到飞机 |
| 用户表达式 | 绑定变量和限定函数 | 新曲线；支持引用已有派生信号，检测循环依赖 |

例如源值 5（二进制 `00000101`），bit0/bit2 为 1，其余为 0。界面显示 bit7…bit0 可便于核对二进制字，但编号始终保持一致。用户可一次创建全部 8 位，再分别命名和定义 0/1 文本标签。

bit0…bit7 的提取建议定义为 `(u >> k) & 1`，k 从 0 开始。MATLAB `bitget` 使用从 1 开始的位号，因此迁移公式时必须明确区别。[官方 bitget 文档](https://www.mathworks.com/help/matlab/ref/bitget.html)

已有 u8 数值列拆位不涉及字节序；以后若支持从多字节载荷解码，才需要另外定义字节序和跨字节位布局。

当前 double 可以精确表示 u8/u16/u32。读取时必须先检查有限、整数、合法范围；不默认截断、取模或把 NaN 当零。不能基于已转 double 的数据声称完整支持所有 u64：超出精确整数范围后需要加载层保留整数存储。

## 建议交互

1. 信号树提供“数据来源 / 对象”切换或分区，避免再占一个常驻宽面板。
2. 多选信号后“创建对象”，或将信号拖入已有对象字段；识别名称只能作为待确认建议。
3. 在对象或对象字段上选择“派生数据”；按所选数据类型展示可用规则。原始信号先通过“绑定到对象”或“创建对象”进入对象管理，不能直接派生。
4. 状态字用表格编辑位号、名称、启用、0/1 标签；实时预览几个样本的十进制/二进制与拆分结果。
5. 公式编辑器通过选择信号建立变量，提供函数插入、类型/时间基诊断和小样本预览，验证后创建。
6. 派生曲线显示在所属对象的“派生数据”分组，可勾选、拖拽、显示游标读数、导出；菜单“查看来源”展示所属对象、规则、输入、单位、时间对齐与错误。派生曲线的编辑与删除回到所属对象管理。
7. 从对象拖入航迹视图时复用位置/姿态绑定；同一对象可用于多个子图，视角、颜色等视图设置由子图管理。
8. 复用对象配置时映射新数据来源并预览。绑定与派生规则随会话保存；可复用配置作为对象模板或扩展现有模板，具体格式在实施前设计，不提前指定新扩展名。

Boolean 和枚举应使用阶梯显示，Boolean 游标可显示 `1（故障）`。这需要确认现有几何/LOD 对离散状态的支持，尤其窄脉冲不能在缩小时悄然消失；不能只生成 0/1 后沿用连续斜线连接就算完成。

## 时间与物理语义

同一个对象不意味着所有字段共享时间轴。单源拆位和换算直接继承原始样本时间，不需要重采样。多源首版建议严格同时间基；不一致时说明原因，不静默插值。

后续显式增加“对齐”规则：选择参考时间轴、匹配方式、最大时间差/间隙、缺失及边界行为。状态量通常适合前值保持，连续量可以选择线性插值；四元数应有专门的姿态插值规则。不得跨长缺口或默认向范围外延用末值。

MATLAB synchronize 将公共时间轴与重采样方式分开配置，这一结构值得借鉴。[官方 synchronize 文档](https://www.mathworks.com/help/matlab/ref/timetable.synchronize.html)

原始信号游标继续访问原始样本；派生信号访问计算生成的样本，并明确标记来源。显式重采样派生结果不应冒充原始测量值，也不改变原始游标规则。

坐标变换派生需要单位、导航/机体坐标系、欧拉顺序、角度单位、四元数顺序和变换方向。加速度需要区分传感器读数和运动学加速度，重力与安装方向不能靠字段名推断。MathWorks IMU 模型分别定义运动学输入、传感器输出、重力与参考坐标系，说明这些语义须显式记录。[官方 imuSensor 文档](https://www.mathworks.com/help/nav/ref/imusensor-system-object.html)

滤波、微分、积分、坐标变换和姿态估计可后续加入，但每个算子都必须给出参数、边界、时间和缺失处理。带噪观测的估计融合属于另一类算子，不作为对象绑定的隐含动作。

## 实现方向与成本

建议新增三个独立概念：稳定身份的 ObjectDefinition、带所属对象/输入/参数/输出身份的 DerivedDefinition、后台 DerivedEvaluator。派生定义形成有向无环依赖图，可一入多出，也可多入一出。创建、恢复与模板应用均校验对象归属，拒绝不存在的所属对象和无归属规则。

计算从原始不可变快照读取，在后台按块执行，支持取消和过期结果丢弃；输出作为计算序列接入既有绘图路径。不从屏幕 LOD、航迹显示缓存或渲染线程计算。只在输入数据、时间偏移或规则改变时使相关缓存失效，颜色和线宽不触发计算。

多输出规则共享同一次输入遍历，时间数组尽量共享；按需求计算并限制缓存。8 条 double 位信号每百万点仅值数组就约 64 MB，若每条再复制时间则额外约 64 MB，尚未包括索引/几何，需考虑紧凑 Boolean 存储和按块输出。

派生来源必须独立于文件/表/列身份，保证会话恢复、来源移除、模板映射、导出和重新计算一致。输入缺失时保留定义并标记无效，不显示旧结果冒充有效结果。删除规则时提示受影响的下游，隐藏曲线不删除规则。

表达式采用限定的原生 C++ 算子与语法解析，函数有明确类型和参数约束。先不选择第三方表达式库：待算子集确定后再核查许可证、整数语义、批量性能和线程安全。不新增 Python API 或绘图库。

ParaView 的来源→过滤器→显示管线、过滤器输入输出及类型约束可作为参考；本项目建议用紧凑表单表达依赖，不必首版引入节点画布。[官方过滤器文档](https://docs.paraview.org/en/v6.0.0/UsersGuide/filteringData.html)

## 分期建议与验收

第一期做完整闭环：对象统一管理、标量/向量/位置/姿态绑定、仅从对象创建派生数据、状态字拆位及位段、比例换算与基础公式、严格同时间基、树中绘图与来源追溯、会话保存和恢复。已有航迹绑定迁移或转换成对象时须预览，旧会话仍可读。

第二期扩展对象模板映射、显式时间对齐、坐标变换、滤波/微分/积分和跨对象比较；根据实际数据选择算子，避免一次铺开所有算法。

一期验收至少覆盖：对象归属校验和禁止原始信号直接派生；对象删除及视图引用清理；u8 取值 0/1/5/128/255，NaN/小数/越界；位号和命名；位段符号；一源多输出；严格多源时间校验；循环依赖；输入修改/移除和缓存失效；取消与过期任务；保存恢复及模板映射；导出来源；大数据内存和 UI 响应；真实 GUI 下的阶梯/短脉冲显示。
