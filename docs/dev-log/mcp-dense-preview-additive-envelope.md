# 密集预览：保留折线的补充包络

2026-09-30

在紧急撤回 `9aa5769` 后重新处理密集 GPS 毫秒曲线的边缘伪凸点。此前原始数据回归表明，预览边缘检查不能替代普通曲线连线检查。本次以恢复版为基线，不恢复全局圆角，也不恢复删除/切断已被包络覆盖的折线段的逻辑。

## 实现约束

- 原折线几何生成路径保持不变，只在其顶点列表后追加包络矩形。
- 仅单调时间、至少 4 样本、Y 方向至少反转两次，且累计绝对变化量达到幅值范围 3 倍的桶作为候选；单调变化、单次阶跃和孤立尖峰不触发。
- 仅实线且桶投影宽度不超过约 1 个逻辑像素时补充包络，不限制屏幕高度。NaN 分段、实际首尾 X 和 min/max 保留；旧桶放大后自动停用补充。
- 极值使用 LOD 点索引，归一化只需继续变换原有点。原始数据、游标查询和峰值选择不变。

## 验证证据

- CPU `denseEnvelopeOnlyAddsCoverage` 逐顶点比较有/无包络版本，证明原线段几何完整保留；覆盖阶跃、单调、孤立尖峰、密集振荡、NaN、虚线及放大。
- `11040237.DAT.mat` 的 GPS 毫秒原始列与合成锯齿波均通过 GPU 检查：1840/1200 两种预览宽度，五档 Y 亚像素偏移，3300–3900 秒恒定上下沿差异均为 0 像素。
- `发动机负载测试.mat` 的航向/俯仰原始列：397.72–397.76 秒跳变连线 162 个 GPU 探测位置缺失为 0。初版补充包络与同尺寸回退版图像相比，原有深色像素丢失为 0、5679 个像素改变；该检查未覆盖线宽，后续发现并修正了加粗问题，详见下文。
- 默认 GPU raster/blend 检查通过；未进行完整应用人工交互、Release、部署和多曲线性能验收。
- 最终 Debug 全构建、qmllint 零 warning，以及 rendercore_test、plotitem_lod_test、appcontroller_test 全部通过。

实际数据 CSV 与 GPU 图像只保存在构建目录，不加入仓库。

## 补充修正：阶跃竖线加粗

用户反馈航向/俯仰阶跃竖线比水平线更宽。仅统计反转次数会把阶跃附近的微小抖动误判成密集振荡；追加包络后仍保留连线，但放大了线宽。新增 GPU 线宽检查在修改前复现：预期 3.5 物理像素，实际最大覆盖宽度 5 像素。

增加累计绝对变化量/桶内幅值范围至少为 3 的条件后，最大实测宽度为 3.74902 物理像素（MSAA 覆盖容差内），跳变周围 17 像素宽区域与回退版逐像素相同，整图原深色像素丢失为 0。162 个连线探测点均通过。GPS 原始数据两种宽度、五档偏移共十组边缘检查仍全部为 0 像素差异。补充带抖动阶跃 CPU 回归。

## 补充修正：共享大范围 Y 轴

GPS 毫秒与 GPS 周内时间共图时，Y 轴扩展至约 20 万，毫秒曲线仅剩约 4 像素高。原有四倍线宽的高度阈值跳过包络，GPU 测试复现上下沿各 1 像素差异。移除屏幕高度阈值，仍保留原始数据振荡判据和横向桶宽限制；这也允许真实微幅振荡使用包络，但不改变阶跃所在桶的判定。新增 `--compressed` GPU 回归。

最终版本验证：GPS 原始数据在正常高度与压缩高度下，各两种宽度、五档偏移均无边缘像素跳动；发动机阶跃仍为 162 个探测位置全部覆盖，最大覆盖宽度仍为 3.74902 物理像素。Debug 构建、qmllint 和三项相关 CTest 均通过。
