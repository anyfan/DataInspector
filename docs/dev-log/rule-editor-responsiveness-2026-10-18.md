# 规则编辑卡顿与默认命名

反馈：新增派生规则切换选项卡顿，规则/输出名称为空。

原因：空的 Y/Z 槽仍用 find 遍历全量 QVariant 候选列表，绑定和拖拽校验也反复线性扫描；点击已绑定输入调用 revealSignal，无条件重置信号树。新增规则未设置初始名称。

修改：空槽直接返回提示，按允许来源快照一次建立 ID/行索引，后续输入查询复用 Map；无搜索且目标已可见时 revealSignal 直接返回行号，保留模型及委托。隐藏目标或搜索状态继续正常清除搜索、展开。新建草稿自动填入未占用的“规则N”，编辑和手动命名不覆盖，取消不占编号。无渲染、计算或会话格式变更。

## 对比证据

同机 Debug、Fusion/offscreen/software，10000 路单点合成 CSV，真实 Main.qml；单次前后采样：

| 操作 | 修改前 | 修改后 |
| --- | ---: | ---: |
| 20 次规则类型切换并处理事件 | 142.600 ms | 30.894 ms |
| 100 轮空槽/末尾来源查询及可用性检查 | 1147.920 ms | 14.963 ms |
| 10 次定位已可见输入 | 170.861 ms | 1.707 ms |
| 定位造成的模型重置 | 10 次 | 0 次 |

原始日志：本地构建目录 rule-editor-before.txt、rule-editor-after.txt。这些是合成数据上的定向诊断，不能等同用户实际 MAT 文件、桌面 GPU 或端到端流畅度验收。自动回归不设耗时阈值，只断言正确性及不重置模型。

## 后续反馈：反复切换 X/Y/Z 与首项默认绑定

上一轮仍保留了 X 自动选择首个候选，并且回归集中在类型切换/方法调用，没有覆盖用户“先点 Y/Z，再依次反复点 X/Y/Z”的窗口事件序列。槽位点击仍附带 browseRuleSource，会切换树栏目、清空搜索或定位列表，反复切换绑定目标会干预树浏览状态。

本次将新建规则的所有输入置空；编辑旧规则仍恢复已有绑定。槽位文字、标签、选择按钮及合并添加按钮共用 activateRuleInput，只切换绑定目标并显示信号树。初次打开编辑页的来源定位独立保留，反复切换槽位不再触发定位/过滤。

补充真实鼠标顺序回归：一万路合成来源，先点 Y/Z，再 10 轮 X/Y/Z；空槽 30 次按钮点击合计约 23.46 ms，绑定到第 0/5000/9999 路后的 30 次标签点击合计约 30.96 ms，模型重置 0，搜索和滚动保持。日志为本地 rule-slot-after.txt。仅证明该合成离屏操作序列，未复现用户实际 MAT/GPU 环境的耗时，不将其称为实际文件完整性能验收。

## 再次复现：点击命中区域

用户最终明确现象为“点了没反应，要反复点才切过去”。此前测试只点击标签中心或按钮，漏掉整块输入槽的留白。现有 Frame 本身没有点击处理，标签 MouseArea 的高度仅覆盖文字，导致大部分可见槽位不能激活变量。点击层改为 Frame 的直接子项，覆盖整个槽位，内容层置于其上以保留按钮行为。放在背景项内的 MouseArea 仍可能被 Control 消耗事件，不能作为替代实现。另为滚动条预留宽度，避免其覆盖卡片右边缘。

新增源码/资源两组命中回归：X/Y/Z 各在左上、上中、下中、左中、右中单击，一次点击即检查 selectedRuleInput，且输入绑定不变；原选择、解除、拖拽路径继续回归。

实际文件在被忽略的 test_file 目录中找到，约 1.5 GB，加载得到 617 路信号。增加编译 QML、D3D11、4 倍 MSAA 的可选真实文件诊断。逐点击 grabWindow 造成的约一秒等待确认属于截图干扰，已从常规测量去除。用户在沙箱外桌面的诊断窗口确认原问题存在，随后将现象明确为点击不生效；不能再把之前的查询加速或纯事件耗时测试当作该问题已解决的证据。

修复整块命中区域后，在同一真实文件、D3D11/4 倍 MSAA 的沙箱外桌面窗口中由用户实际点击确认“现在单击就能切换”。该次记录中切换处理约 0.3～0.7 ms，首次显示帧约 21～23 ms；日志为本地 rule-real-desktop-hit-area.txt。临时诊断窗口确认后关闭，正式 Debug/Release 程序使用同一 QML 修复。
